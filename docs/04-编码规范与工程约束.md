# AegisID 编码规范与工程约束

## 1. 基本原则

- 代码遵循阿里 Java 开发手册的主要约束。
- 新代码必须通过 Maven Enforcer、Checkstyle 和编译检查。
- Controller 不写业务逻辑，Service 不直接操作 Mapper，Mapper 不暴露到接口层。
- 安全相关信息默认按敏感信息处理，包括 password、secret、token、authorization code、refresh token、private key。

## 2. 后端分层约束

推荐包结构：

```text
application/
  command/
  query/
  service/

domain/
  model/
  repository/

infrastructure/
  persistence/
    entity/
    mapper/
    repository/

interfaces/
  controller/
  request/
  response/
```

约束：

- `interfaces.controller` 只负责 HTTP 入参、出参和状态码。
- `interfaces.request` 使用 Validation 注解校验入参。
- `interfaces.response` 不直接返回数据库 Entity。
- `application.service` 负责业务编排、事务边界和领域规则。
- `domain.model` 表达业务对象，不依赖 MyBatis、Spring MVC 等框架。
- `domain.repository` 只定义持久化语义。
- `infrastructure.persistence.mapper` 只操作数据库。
- `infrastructure.persistence.repository` 负责 Entity 与 Domain 转换。

## 3. 命名与常量

- 禁止在业务代码中散落魔法值。
- 状态值、协议值、权限模式、事件类型应定义为常量或枚举。
- 常量名使用大写下划线。
- 数据库字段使用小写下划线。
- Java 字段使用 lowerCamelCase。
- 布尔字段不要使用 `isXxx` 作为字段名，使用 `enabled`、`required`、`visible` 等语义名称。

## 4. 产品文案约束

- 后台管理页面优先使用业务语言，不把协议名、数据库名、接口名直接作为主按钮、主标题或主导航。
- 技术术语可以作为补充说明出现，但主文案必须让普通管理员能理解。
- `OAuth Client`、`OIDC Client` 面向用户统一表达为“登录接入配置”或“登录接入”。
- `Client ID` 面向用户表达为“接入标识”，必要时写作“接入标识（Client ID）”。
- `Client Secret` 面向用户表达为“接入密钥”，必要时写作“接入密钥（Client Secret）”。
- `scope` 面向用户表达为“授权范围”，必要时写作“授权范围（scope）”。
- `redirect_uri` 面向用户表达为“登录成功回调地址”或“回调地址”。
- 技术设计文档、接口字段、代码类型、数据库字段可以保留标准协议术语，但必须避免影响页面文案。

## 5. 异常与错误码

- 业务异常统一使用 `BusinessException`。
- 对外错误码统一从 `ErrorCode` 扩展。
- 不允许把底层异常堆栈直接返回给前端。
- 参数校验异常返回 `INVALID_REQUEST`。
- 资源不存在返回 `RESOURCE_NOT_FOUND`。
- 唯一键、重复编码、重复名称返回 `RESOURCE_CONFLICT`。
- 安全校验失败使用具体错误码，如 `INVALID_REDIRECT_URI`。

## 6. 日志

- 日志必须有明确动作和上下文。
- 禁止打印 password、secret、token、authorization code、refresh token、private key。
- 异常日志可以记录错误码、资源 ID、client_id、app_code，但敏感值必须脱敏。
- Controller 不主动打印业务成功日志，重要审计事件后续进入审计模块。
- 全局异常处理器记录未知异常，业务异常默认不打印堆栈。

## 7. 事务

- 写操作必须在 Application Service 层声明事务。
- 查询操作默认不加事务；复杂一致性读取按需加只读事务。
- Repository 和 Mapper 不声明业务事务。
- 不在事务内调用不稳定外部系统，如短信、Webhook、第三方 IdP。

## 8. 数据访问

- 使用 MyBatis Plus 作为基础 Mapper 技术栈。
- 简单 CRUD 可用 `BaseMapper`。
- 复杂查询优先写清晰 SQL 或 XML。
- Service 不直接注入 Mapper。
- Repository 负责屏蔽表结构、字段名和 Entity。
- 数据库迁移使用 Flyway，禁止依赖手工建表。

## 9. 安全约束

- 密码、client_secret、refresh_token、authorization_code 只存 hash。
- Secret 明文只允许创建时返回一次。
- redirect_uri 必须精确匹配，禁止通配符。
- 非 localhost 场景只允许 HTTPS redirect_uri。
- Token、Secret、密码不得进入普通业务日志。
- 管理员敏感操作后续必须写审计日志。

## 10. API 约束

- API 返回统一使用 `ApiResponse`。
- 列表接口必须分页，当前临时列表接口在正式页面接入前需要补分页。
- Request 与 Response 对象必须独立定义，禁止直接暴露 Entity。
- 入参必须使用 Validation 注解。
- URL 使用复数资源名，如 `/api/admin/applications`。
- 启用、禁用、生成 Secret 等命令动作使用 POST。

## 11. 测试约束

- 核心 Service 需要单元测试。
- Controller 需要接口层测试。
- Repository 和 Flyway 迁移需要集成测试。
- Secret、Token、权限、登录相关逻辑必须覆盖异常路径。
- 每次提交前至少执行：

```powershell
mvn -f backend\pom.xml test
npm --prefix frontend/admin-console run build
```
